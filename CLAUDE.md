# Neon Invasion remake

Read this file first, then `NOTES.md`. This file holds the rules, which change rarely. `NOTES.md` is the running log: what was done, what was verified, and what has not been checked yet. Update `NOTES.md` at the end of every task.

## What this project is

Neon Invasion is a browser first-person co-op shooter: neon 1980s beach city, waves of aliens, shops, vehicles, solo or multiplayer. This folder is a visual and audio remake of the released build. The game rules stay as they were. The remake replaces how the game looks, sounds and feels.

How it is built:

- **No build step, no package manager, no modules.** Everything is plain `<script>` tags. The game must keep working from a static file server, and from opening `game.html` directly. Do not add npm, bundlers, ES `import`, TypeScript, or `fetch()` of local files.
- **three.js r128**, vendored as `three.min.js`. Do not upgrade it. The render core patches r128 shader source by string replacement, and a different version breaks those patches.
- **Original game code** lives in `game.html` (one large inline script inside one function) and `shared.js` (the simulation, also run by the multiplayer server).
- **The remake layer** lives in `nx/`. It creates one global, `window.NIX`. `game.html` calls into it at hook points, each marked with a `REMAKE:` comment.
- **Every 3D model is made in Blender by Python scripts** in `blender/`. They write all geometry into one generated file, `nx/nx-assets.js`. Code in the browser only animates models and draws effects.
- Script load order in `game.html` matters: `three.min.js`, `shared.js`, `nx-assets.js`, `nx-core.js`, `nx-models.js`, `nx-props.js`, then the game.

## Commands

All commands run from this folder, in PowerShell. The machine has Blender 5.3 from Steam. It has no Node and no real system Python, so use Blender's bundled Python.

**Run the game** (static server on port 8642):

```
& "C:\Program Files (x86)\Steam\steamapps\common\Blender\5.3\python\bin\python.exe" -I -m http.server 8642 --bind 127.0.0.1
```

Then open `http://localhost:8642/game.html`. If the browser preview tool has a `remake` server configured, start that instead. Add `?dev=1` for dev mode (see Testing).

**Rebuild the models** (about 1 minute, overwrites `nx/nx-assets.js` and the `.blend`):

```
& "C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe" --background --factory-startup --python blender\build_assets.py -- nx\nx-assets.js blender\neon_invasion_assets.blend ..\preview_assets.png
```

The output must contain `30 enemy designs` and no `Traceback`. The last argument writes contact-sheet images; leave it off to skip rendering.

**Test.** There is no automated test suite and no linter. Testing means loading the game in a browser and checking numbers. See "Testing" below.

**Package.** Zip this folder as `NeonInvasion-Remake.zip`. Leave out `.blend1` backup files.

## How to work here

- **Search before reading.** `game.html` is 600 KB. Use Grep to find the place, then Read with `offset` and `limit`. Find sections by their banner comment, not by line number, because line numbers move.
- **Exclude the big files from every search.** A match in `nx/nx-assets.js` or `three.min.js` returns megabytes. Search `game.html`, `shared.js`, `nx/nx-core.js`, `nx/nx-models.js`, `nx/nx-props.js` and `blender/*.py` by name.
- **Edit, do not rewrite.** Change existing files with small targeted edits. Never regenerate a whole file.
- **Batch browser actions.** One batch per test. Reload only when code changed.
- **Verify with numbers, not screenshots.** The owner asked for this. Use `NIX.info()`, console errors, and positions.
- **Report honestly.** Say what you ran and what you did not. "Checked by numbers, not by eye" is a normal and required statement here.

## Coding rules

1. **Do not change `shared.js`.** It is the game's rules and it also runs on the multiplayer server. A change there alters balance and can break online play. Visual work goes in `nx/` and in `game.html`. If a task truly needs a rule change, stop and ask.
2. **Mark every change in `game.html` with a `REMAKE:` comment** that says in plain words what it does and why. `Grep "REMAKE:"` must list every hook.
3. **Keep the fallback at every hook.** The pattern is `if(!(NIX.thing&&NIX.thing(args))){ ...original code... }`. If an asset or `nx/` file is missing, the game still runs with the old boxes. Never delete the original branch.
4. **Bump the script version after changing any `nx/` file.** The four `nx/` script tags in `game.html` share one `?v=N`. Raise all four together.
5. **Match the existing code style.** Dense lines, short local names, `const`/`let`, arrow functions, 2-space indent, semicolons. Each `nx/` file is one strict-mode function that returns early if `NIX` or `THREE` is missing. Comments explain why in plain English. Do not reformat code you are not changing.
6. **Never assume 60 frames per second.** Movement and timers use `dt`. World effects use `FXDT`. Smoothing uses `1-Math.exp(-rate*dt)`. The game runs from 30 to 240 fps.
7. **Do not allocate inside the frame loop.** Reuse the scratch vectors, matrices and colours declared at the top of each section.
8. **Shader patches.** Use the `patch(mat, fn, key)` helper in `nx-core.js`: it sets the program cache key and marks the material. Share uniforms through `NIX.U`. Prefix every added GLSL name with `nx`. Guard each string replacement so a missing anchor leaves the stock shader working.
9. **Know what the batcher does.** About 40 frames after the world is built, every static mesh with a plain Lambert or Basic material is merged into a few large meshes per city cell. Consequences:
   - A mesh that the game later moves, hides, re-parents or re-materials is pulled back out automatically, and each one costs a draw call. Watch `NIX.info().batch.unbatched`.
   - Changing the colour of a shared material pulls out every mesh that uses it. Give animated things their own material.
   - Set `mesh._nxNo=1` before adding a mesh that must never be merged. `_nxNoCast=1` and `_nxNoRecv=1` turn off shadow casting and receiving.
   - `Object3D.add` is patched to set shadow flags on meshes. Set `_nxF=1` to skip that.
10. **Many copies of one model go through `NIX.scatter`,** which splits them into city cells so they cull, with an optional far model. It draws with its own copy of the material you pass (returned as `group.userData.mat`), and that copy fades each instance by distance so nothing pops in or out. Never hide scattered things with a hard distance test. three.js r128 turns frustum culling off for every `InstancedMesh`; `NIX.scatter` turns it back on, and any other `InstancedMesh` you add needs a bounding sphere and `frustumCulled=true`.
11. **Solids are client-side and on-foot only.** `NIX.addSolid(x,z,radius,height)` blocks the local player on foot. Cars, the gunship and aliens ignore it, because their movement is in `shared.js`. Do not use solids to close a street.
12. **Model changes go through Blender.** Edit `blender/*.py`, rebuild, bump `?v`. Asset names are contracts read by `nx/` code: `gunN_body/_detail/_accent`, `carN_body/_detail/_trim/_lights`, `st_<name>_body/_glow`, `ico_*`, `mbox_*`, `loot_*`, `roof_*`, `palm_hi/lo`, `lamp_post/glow`, `aN_*`, `lm_<name>_body/_glow` (plus `lm_gondola`, `lm_crate`, `lm_crystal`, `lm_container_detail`, `lm_kiosk_trim`).
13. **Mind the two coordinate systems.** Blender: +Z up, guns point +Y, aliens face -Y. Game: +Y up, -Z forward. `export()` converts. `props.py` is written in game space through the `g*` wrappers (front of a vehicle is +z). Do not mix raw helpers and `g*` wrappers in one model.
14. **Do not rename saved keys or ids.** Browser saves use `ni_set`, `ni_gfx`, `ni_fps`, `ni_tut1`, `ni_dev`, `ni_name`, `ni_url`, `ni_best_v1`, and the `ni_clips` database. Perk and achievement ids are stored in player saves.
15. **Leave the aliens alone unless asked:** `aliens.py`, `NIX.makeAlien`, the `a*` assets, and the Dex data. If you are asked to change one, its hit zones are computed in `shared.js` (`godzSpheres`, `cleoSnakePos`) and the model must still match them. The Overmind's `o.bm` setter in `makeAlien` must keep working.
16. **No debug handles in shipped code.** The game's state is private to its function. If you need a temporary handle to test, add it, test, and remove it in the same task.

## Design rules

Look: a 1986 neon beach city at sunset. Saturated pink, cyan and violet on dark indigo. Warm sun by day, cool blue at night.

**3D**

- Glowing things are `MeshBasicMaterial`. The render core pushes bright, saturated unlit colours above 1.0 so the bloom picks them up. Lit things are `MeshLambertMaterial` with vertex colours. Do not make a lit surface glow by raising its colour.
- Every lit prop shares one surface treatment (sky-tinted edge sheen, soft sun glint, darker near the ground), added to Lambert in `nx-props.js`. Do not add per-prop lighting tricks.
- Colour is painted per face in Blender. The alpha of a colour is how much that surface glows.
- Vehicles: `_body` is white shades that the paint colour tints; `_detail` keeps true colours; `_trim` is one neon colour; `_lights` are unlit.
- Bevel hard edges. Flat unbevelled boxes are the look this remake replaces.
- Each enemy and vehicle must be recognisable by silhouette alone in a crowd.
- Models drawn many times (aliens, lamps, crates, rooftop kit) are built with `LOW = True`.
- Sky, fog and light colours come from the `PAL` and `TP` tables in `game.html`. Use them instead of new hard-coded colours.

**UI**

- All restyling lives in one CSS block at the end of the `<style>` in `game.html`, headed `REMAKE: one UI language`. It changes looks only. Do not change element ids, layout, or behaviour to restyle something.
- Use the tokens: `--pk` pink for primary actions, `--cy` cyan for secondary and information, `--gd` gold for money and rewards, `--gn` green for good, `--rd` red for danger, `--vi` violet, `--or` orange.
- Type: `--ui` (Chakra Petch) for text, `--num` (Orbitron) for numbers and headings. Uppercase with wide letter spacing.
- Surfaces: dark glass panels (`--panel`), 12px corners, 1.5px borders, a cyan hairline, a soft violet glow (`--glow`). Bars and pills are fully rounded.
- Google Fonts is the only network dependency. Every font has a local fallback; keep it.
- In-game text is short, uppercase and dry. Example: "THIS IS NOT IN THE BROCHURE".
- Keep the accessibility settings working: flashing effects toggle, colourblind map colours, large HUD text, reduced motion, controller navigation and focus ring.

**Sound**

- Effects are layered (attack, body, low end, tail) with a small random pitch change, and all go through the `sfxBus` mix bus. New sounds use the shared noise buffer (`nzSrc`), not a new buffer per sound.

**Performance budget** (level 1, solo, 1080p, on this machine)

- 60 fps or better, GPU time under about 12 ms, around 750 draw calls, around 350k triangles, about 46 batch chunks. A change that moves these noticeably needs a reason.
- Expensive features must be tied to a quality preset in `PRESETS` so LOW stays cheap.

## Mistakes a weaker model makes here, and how to avoid each

| Mistake | Do this instead |
|---|---|
| Opening or grepping `nx/nx-assets.js` or `three.min.js` and flooding the context. | Never read them. Name the files you search. To learn which assets exist, grep `export('` and `reg(` in `blender/*.py`. |
| Reading `game.html` from top to bottom. | Grep for the banner comment or function name, then read 40 to 100 lines around it. |
| Hand-editing `nx/nx-assets.js`. | Edit `blender/*.py` and rebuild. |
| Editing `shared.js` to fix something visual. | Put it in `nx/` or `game.html`. `shared.js` must stay identical to the released build. |
| Deleting the original box-built code because the new model replaces it. | Keep it as the fallback branch. |
| Changing `nx/` code and then testing a stale copy. | Bump `?v=N` on all four tags. The preview server also caches hard: run `fetch(url,{cache:'reload'})` for each changed file, then reload. |
| Measuring frame rate while the browser pane is hidden or in the background. | A hidden page renders no frames, so the numbers are false. Confirm the pane is visible. Wait 5 seconds after starting a match: the first 4 seconds are a warm-up and the batcher needs 40 frames. |
| Reading 30 fps as a slow game. | Check `NIX.info().refresh` and the frame-rate limit setting. The cap may be the screen or the limiter. |
| Typing game variables into the console (`me`, `scene`, `S`). | They are private. Only `NIX` and `NI` are global. Use `NIX.info()`, dev mode, or a temporary handle that you remove. |
| Adding a mesh that moves, then finding draw calls climbed. | Set `_nxNo=1` on it before adding, and give it its own material. |
| Animating the colour of a material that many static meshes share. | Clone the material for the animated mesh. |
| Using Lambert for a neon tube, or Basic for a wall. | Neon is Basic. Lit surfaces are Lambert. |
| Writing `x += 0.02` per frame. | Multiply by `dt` or `FXDT`. |
| Writing a Blender part in the wrong axis, so it comes out sideways or mirrored. | Check the header comment of the file you are in. `props.py` uses game space through `g*` wrappers. Everything else uses Blender space. |
| Replacing a shader chunk with a string that does not exist in r128, which fails without an error. | Test the anchor with `indexOf` or a regex first. After the change, check the console for shader errors and confirm the effect with a number. |
| Restyling a screen by changing its HTML, ids or JavaScript. | Add CSS to the `REMAKE: one UI language` block, using the tokens. |
| Inventing new colours or fonts. | Use the CSS tokens and the `PAL` table. |
| Introducing npm, modules, a framework or a new three.js. | Plain scripts only, r128 only. |
| Saying "it looks great" after checking only numbers. | Say exactly what was checked. List what needs the owner's eyes or ears. |
| Taking screenshots to verify. | Use numbers. The owner turned screenshots off. |
| Redesigning aliens or "tidying" `aliens.py` while passing through. | Leave them unless the task asks for it. |
| Expecting `NIX.addSolid` to stop aliens or cars. | It stops only the local player on foot. |
| Leaving a debug handle or `console.log` in place. | Remove it before finishing. |
| Finishing without updating `NOTES.md`. | Record what changed, what was verified and how, and what was not verified. |

## Testing

There is no test runner. A test is a short browser session.

1. Start the server. Open `http://localhost:8642/game.html?dev=1`. Dev mode has its own save, unlocks everything, and adds a start-round picker on the menu. In a solo game, F8 opens the dev panel: money, god mode, jump to a round, spawn any alien or boss.
2. Click PLAY SOLO. Wait 8 seconds.
3. Read console errors only (errors filter, small limit). The one known harmless error is a 404 for `/07.mp3`, which falls back to `/radio/07.mp3`.
4. Run `JSON.stringify(NIX.info())`. Check `calls`, `tris`, `fps`, `gpuMs`, `scale`, `res`, and `batch` (`chunks`, `unbatched`, `state` should be 2).
5. For a collision test, record the player position before and after moving into the object.
6. For a quality change, repeat step 4 at `NIX.setQuality(0)` through `NIX.setQuality(3)`.

If the mouse lock is lost, the game shows "CLICK TO RESUME" and solo pauses. Click the canvas before measuring.
